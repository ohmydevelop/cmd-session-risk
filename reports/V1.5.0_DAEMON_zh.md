# v1.5.0：HTTP 打分守护进程（`cmdrisk serve`）发布报告

日期：2026-09-24（America/New_York）。本次发布**新增**一个持续运行的 HTTP
打分守护进程，**不删除、不改变** v1.4.2 的批量 CLI 行为。

## 1. 目标与形态

- 单一二进制继续承载两种模式：`cmdrisk input.txt [threshold]`（批量）与
  `cmdrisk serve [--bind 127.0.0.1:8080] [--max-body 1048576] [--timeout 5]`（daemon）。
- 模型/词表/校准/配置依旧**编译期内嵌**，无 Python、无第三方库、无动态依赖；
  新增 HTTP/1.1 server 与 JSON 解析器为手写 C（约 500 行，长度受限、深度受限、边界安全）。
- 地表约束：单线程串行（accept→读→解析→推断→回包→close），每个响应
  `Connection: close`；套接字读写超时默认 5s；单会话命令上限 1024；默认仅监听
  `127.0.0.1` 且**无鉴权**，绑定到非回环地址会在启动时打印警告。

## 2. 与旧方案（批量 CLI / Python ONNX 管线）的对比

| 维度 | v1.4.2 批量 CLI | v1.5.0 `serve` daemon |
|---|---|---|
| 推理路径 | `cmdrisk_single.c` 内联 | 与批量**共用** `cmdrisk_score_prefix()` |
| 恶意概率 | 同一 FP32 权重 + 同一温度缩放 | 位级一致（smoke 断言容差 0） |
| 阈值/温度来源 | 内嵌 `calibration.json` | 同一份内嵌 `calibration.json` |
| 意图层（确定性 10 类） | 有 | 有（`intent_classes` 原样透出） |
| 输出粒度 | 每行一个完整前缀 | 每请求 N 个逐前缀 `answers` |
| 常驻内存 | ~30 MiB（进程级） | VmHWM 实测 31.0 MiB |
| 调用方式 | 离线文件 | HTTP `GET /healthz` + `POST /v1/score` |

结论：daemon 是批量 CLI 的**在线化封装**，不是新的评分模型；两者概率天然一致，
旧二进制与旧 release 全部保留（回归 smoke 8/21/28 行断言原样通过）。

## 3. HTTP 契约

- `GET /healthz` → 200
  `{"ok":true,"model":"v6","version":"v1.5.0","bind":"127.0.0.1:8080"}`
- `POST /v1/score`
  - 请求：`{"session_id":"s1","commands":["id","rm -rf /"]}`；命令可为字符串或
    `{"cmd":"...","dt":0.5}`；`session_id` 可选（缺省 `sess-<pid>-<seq>`）。
  - 响应：`answers` 逐前缀返回 `command_index / malicious_probability /
    risk_score / attack_stage / intent_classes / tactic / technique / alert`
    + 会话级 `peak_probability / alerted / model_version / schema_version`。
  - `alert = (prob >= threshold) || intent 命中`，定位仍是**告警 + 人工复核，不阻断**。
- 错误码：400 `invalid_json`/`invalid_request`、404、405（带 `Allow`）、
  408 `request_timeout`、413 `payload_too_large`、500 `inference_error`。

## 4. 验收结果（本机 + `scripts/serve_smoke.sh` 全过）

- 恶意单命令 `rm -rf /`：`alerted=true`，`intent_classes=destructive_delete`，
  `peak_probability=0.995549321`，与批量 CLI 同份概率（差 < 1e-12）。
- 多命令会话逐前缀：`[0,1,2]` 三个 `answers`，威胁前缀正确置 `alert=true`。
- 良性 `echo hello world`：`alerted=false`，tactics/techniques 为 `-`。
- 错误路径：非法 JSON 400、空 commands 400、未知路径 404、方法错误 405、超
  `--max-body` 413。
- 性能：3 命令会话串行 ~88 ms/请求；50 次连续请求 4.39 s 无失败。
- 资源：`VmHWM=31760 kB`（31.0 MiB，< 60 MiB 门限）。

## 5. 已知边界与后续方向

- `attack_stage/tactic/technique` 使用 C 侧的 argmax 单标签（与既有 C runtime 相同），
  与 Python 管线“带阈值的多标签 argmax”在极端边缘可能有差异；数值大头
  `malicious_probability` 与决策路径两条管线一致。
- `serve` 暂不支持 IPv6 绑定与并发请求并行处理；后续需要再做 `select/epoll`/多进程。
- 未提供鉴权/TLS；生产跨机部署应由反向代理统一处理。
- 生产定位：作为告警数据源与 SIEM/审计流程联动，人工复核后再处置。
